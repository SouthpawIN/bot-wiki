# NRCU roster manifest — source audit

**Job.** `kart-racer:character-audit`. One entry per canonical NRCU character, every
fact traceable to the file it came from, every gap named instead of filled.

**Source of truth.** [`123mikeyd/Nous_Research_Cinematic_Universe`](https://github.com/123mikeyd/Nous_Research_Cinematic_Universe)
at `b1e0b2a` — read from a fresh clone on 2026-11-16, not from a description of it.
`characters/README.md` is the cast directory: **35 canonical entries**. Three
more files sit in `characters/` and are *not* separate characters — see
"Alias files" below.

**Rule this file is written under** (from `BOT.md`, "Character rules"):

- Every character is the canonical sheet design — no restyle, no renamed variant.
- At work, in role; not posing.
- **No invented accessories, props or vehicles.** A missing vehicle is marked
  `[[UNSOURCED]]`, never designed. Inventing a kart is the same error class as
  inventing a hat.
- If a sheet is ambiguous or missing a view, flag it and reuse the closest
  canonical depiction.
- Turbo Fit / Sovthpaw keeps the spelling in the game and is credited as `sovthpaw`.

**Legend.** `present` = a character image ships and resolves on disk. `sheet-page`
= no portrait on the profile page but `characters/sheets/<slug>.md` carries art.
`none` = no character art anywhere in the source. `[[UNSOURCED]]` = the source does
not say, so nothing is claimed.

promote a guess to canon.

### The generated `assets/roster.json` is not source-faithful
The audit surfaced a real defect in `scripts/roster.py`: weight class comes from a
plain substring scan, so it fires on words that happen to contain a hint.
`source_note` records the accident verbatim, which makes it auditable and wrong:

- `fleety` and `tdamre` → **light** on `'bee'` inside *"has not **bee**n recorded"*.
- `don-piedro`, `mephisto`, `noctis`, `teknium`, `quark2world` → **heavy** on `'mech'` inside *"**mech**anical"*, *"**mech**anics"*, *"**mech**a sheet"*, *"industrial **mach**ine"*-class words.
- `doge-man` → **light** on `'cat'` inside *"**cat**alogued"*.
- `scary-jerry`, `sudo-nightwing` → **light** on `'imp'` inside *"**imp**ressive"*, *"**imp**acts"*.
- `cthulhu` → **heavy** because its own name is in the hint list — circular.
- **turbo-fit → light**, from `'small'` in *"a **small** home workspace"*. Sovthpaw is 6'1", lean/athletic. This one is corrected below because it is the operator's avatar.

**Fix applied:** `weight_class()` now matches whole words (case-insensitive), not
substrings, and splits CamelCase display names so `FatCat` still yields "cat". The
new test `test_weight_class_reads_whole_words_not_substrings` locks that in.

**No silent rebalance.** Rebuilding under the fixed matcher would drop **14**
characters to the `medium` default (29 medium / 5 light / 1 heavy), which is honest
but flat and would churn a roster mid-project. So the shipped classes that rested on
a substring are now **pinned** (`locked: true`) with a `source_note` that says
plainly: *"hand-tuned class, pinned… a gameplay decision, not a source claim."* The
shipped distribution is **16 medium / 13 light / 6 heavy** (was 15/14/6). Exactly one
entry moved: **turbo-fit, light → medium**, because its class contradicted its own
profile ("small home workspace", not small person), with a `source_note` quoting the
build line and a hand-set medium stat line marked as hand-set.
